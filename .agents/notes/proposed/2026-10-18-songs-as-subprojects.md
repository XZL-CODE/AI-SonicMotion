# Agent Note: 仓库按"一首歌一个二级项目"组织

Status: proposed

## Problem

仓库以后会存放多首歌，每首都有自己的歌词、画面和发布物料，需要定下目录怎么分、每首歌必须交付哪些东西。

## Proposal

- 仓库 AI-SonicMotion 是一级项目：根 README 列出全部作品；生成、分析、渲染程序放在 `engine/`，各首歌共用。理由：程序只写一份，改进对所有歌生效。
- 每首歌是根目录下并列的二级项目，自带 README（歌名、简介、歌词）、`song.json`、本曲的 `scenes.py`、输入素材和 `covers/`；生成结果放在本曲的 `outputs/`，不入库。理由：一首歌的东西都在一个目录里，新增一首不影响其他歌。
- 每首歌都要做 B 站和公众号封面，按这首歌的内容与画面单独设计、手写 SVG，不用固定模板或脚本生成；导出 JPG 一起入库。B 站为 16:9，文字放在中间 4:3、避开底部角标；公众号为 2.35:1，信息全部放在中间 600×600，另出 1:1 方图。理由：封面要跟着这首歌走；安全区是平台裁切和角标的硬约束。
- 封面与对外文字遵循同一条个人信息边界：不出现可识别的个人信息。
